# Handoff: Lenslate Brand Implementation

> **For Claude Code.** This is a complete, self-contained plan to rename the product to **Lenslate** and apply its temporary brand identity in the `Focals-Base` codebase (`my-app/`, Next.js 15 App Router). Work through the steps in order. Everything you need — exact files, exact code, exact tokens — is below. You should be able to complete this without further input.

---

## 1. Overview

The app (codename **Focals Base**) reads its display name from the `NEXT_PUBLIC_APP_NAME` env var and renders it as plain text in two places (sidebar + login). There is no logo/mark yet.

This task:
1. Sets the product name to **Lenslate** everywhere it surfaces.
2. Adds a small, reusable **`<Wordmark>`** brand component — the name in the existing Canela display serif followed by a bone "lens dot" — and uses it in the sidebar and login.
3. Adds a **placeholder app icon / favicon** (a bone serif "L" on a dark tile) that the user will replace later.

This is **Direction A**, the single approved direction. It is intentionally restrained and editorial — it must match the app's existing dark-first aesthetic (Acne Studios / Linear / Vercel references).

---

## 2. About the design files

`Lenslate Brand.html` (+ `brand.jsx`, `design-canvas.jsx`) in this folder are an **HTML design reference** — a prototype showing the intended look. They are **not** code to copy verbatim. The login card and sidebar in the prototype are faithful reconstructions of the real components, so use them to confirm spacing/proportion, but implement against the **real** components in `my-app/src`.

Open `Lenslate Brand.html` to see: the wordmark (dark + light), the app icon at 132/56/32px, and the branded login + sidebar.

**Fidelity: High.** Colors, type, and the lens-dot proportions are final for this placeholder phase. Reproduce them exactly using the values in §7.

## 3. Step 1 — Set the product name

The name comes from one env var. Update both files:

**`my-app/.env.local`** and **`my-app/.env.local.example`**
```bash
NEXT_PUBLIC_APP_NAME=Lenslate
```

This automatically fixes every page `<title>` (e.g. `Dashboard · Lenslate`), the iCal feed name, the contract PDF footer ("Generated by Lenslate"), and the mobile nav fallback title — they all already read this var. **No code change needed for those.**

> ⚠️ **Do NOT change** the string `'focals-llm-key-salt'` in `my-app/src/lib/llm/encryption.ts`. It is a cryptographic salt, not branding — changing it makes already-encrypted user API keys undecryptable.

After this step, grep for any remaining hardcoded brand copy and review case-by-case (most are docs, safe to update):
```bash
grep -rni "focals" my-app/src
```
Update human-facing copy (help content, comments shown to users) to "Lenslate"; leave internal identifiers, the salt above, and the `my-app/my-app` folder name alone.

## 4. Step 2 — Add the `<Wordmark>` brand component

Create **`my-app/src/components/brand/Wordmark.tsx`**. This is the single source of truth for the lockup, so the dot can never drift between surfaces. The dot is sized in `em`, so it scales correctly at any font size.

```tsx
import { CSSProperties } from 'react';

const APP_NAME = process.env.NEXT_PUBLIC_APP_NAME ?? 'Lenslate';

type WordmarkProps = {
  /** Display size, e.g. '1.125rem' (sidebar) or '2.25rem' (login). */
  fontSize?: string;
  /** Tighter tracking reads better at large sizes. */
  letterSpacing?: string;
  color?: string;
  style?: CSSProperties;
};

/**
 * Lenslate wordmark — name in the display serif (Canela) followed by a
 * bone "lens dot". Temporary identity; the dot is the only mark for now.
 */
export function Wordmark({
  fontSize = '1.125rem',
  letterSpacing = '-0.01em',
  color = 'var(--color-text-primary)',
  style,
}: WordmarkProps) {
  return (
    <span
      style={{
        display: 'inline-flex',
        alignItems: 'flex-end',
        fontFamily: 'var(--font-display)',
        fontSize,
        fontWeight: 500,
        letterSpacing,
        color,
        lineHeight: 1,
        whiteSpace: 'nowrap',
        ...style,
      }}
    >
      {APP_NAME}
      <span
        aria-hidden="true"
        style={{
          width: '0.16em',
          height: '0.16em',
          borderRadius: '50%',
          background: 'var(--color-accent)',
          marginLeft: '0.12em',
          marginBottom: '0.14em',
          flex: '0 0 auto',
        }}
      />
    </span>
  );
}
```

## 5. Step 3 — Use it in the sidebar

**`my-app/src/components/layout/Sidebar.tsx`** — in `NavBody`, the brand `<Link href="/">` currently renders `{process.env.NEXT_PUBLIC_APP_NAME}` directly. Keep the `<Link>` (it's the home-nav target); swap its text child for `<Wordmark>` and drop the now-redundant font styles from the Link (the component owns them).

Replace:
```tsx
<Link
  href="/"
  prefetch={true}
  onClick={onNavigate}
  style={{
    padding: '0 0.75rem',
    fontFamily: 'var(--font-display)',
    fontSize: '1.125rem',
    fontWeight: 500,
    color: 'var(--color-text-primary)',
    textDecoration: 'none',
    letterSpacing: '-0.01em',
  }}
>
  {process.env.NEXT_PUBLIC_APP_NAME}
</Link>
```
with:
```tsx
<Link
  href="/"
  prefetch={true}
  onClick={onNavigate}
  style={{ padding: '0 0.75rem', textDecoration: 'none' }}
>
  <Wordmark fontSize="1.125rem" />
</Link>
```
Add the import: `import { Wordmark } from '@/components/brand/Wordmark';`

## 6. Step 4 — Use it in the login screen

**`my-app/src/app/(auth)/login/page.tsx`** — the `<h1>` renders `{process.env.NEXT_PUBLIC_APP_NAME}`. Keep `<h1>` for semantics; put the wordmark inside it and use the larger size + tighter tracking.

Replace:
```tsx
<h1
  style={{
    fontFamily: 'var(--font-display)',
    fontSize: '2.25rem',
    color: 'var(--color-text-primary)',
    margin: 0,
    letterSpacing: '-0.02em',
  }}
>
  {process.env.NEXT_PUBLIC_APP_NAME}
</h1>
```
with:
```tsx
<h1 style={{ margin: 0 }}>
  <Wordmark fontSize="2.25rem" letterSpacing="-0.02em" />
</h1>
```
Add the import: `import { Wordmark } from '@/components/brand/Wordmark';`

> The login page is a Server Component and `process.env.NEXT_PUBLIC_*` is inlined at build time, so the wordmark renders server-side with no flash. Fine as-is.

## 7. Step 5 — Placeholder app icon / favicon

The repo currently ships `my-app/src/app/favicon.ico` (old). In the App Router, a `src/app/icon.svg` takes precedence and auto-wires `<link rel="icon">`. Create **`my-app/src/app/icon.svg`**:

```svg
<svg xmlns="http://www.w3.org/2000/svg" width="64" height="64" viewBox="0 0 64 64">
  <rect width="64" height="64" rx="15" fill="#111111"/>
  <rect x="0.5" y="0.5" width="63" height="63" rx="14.5" fill="none" stroke="#2a2a2a"/>
  <text x="32" y="46" text-anchor="middle"
        font-family="Canela, Georgia, 'Times New Roman', serif"
        font-size="42" font-weight="500" fill="#e8e0d0">L</text>
</svg>
```
Also add **`my-app/src/app/apple-icon.svg`** with the same contents (Next.js serves it as the Apple touch icon). Delete `favicon.ico` only after confirming the SVG icon loads.

> The browser will render the "L" in Georgia (Canela isn't loaded in the favicon context). That's acceptable for a placeholder; the user replaces this with the final logo. If you want the real Canela shape baked in, convert the glyph to an SVG `<path>` using the licensed font before exporting — otherwise leave the `<text>` version.

## 8. Design tokens (already defined in `globals.css`)

Use these exact values; do not invent new ones. They exist as CSS variables — reference the variables, not raw hex, in components.

| Token | Dark | Light | Used for |
|---|---|---|---|
| `--color-bg` | `#0a0a0a` | `#ffffff` | page background |
| `--color-bg-secondary` | `#111111` | `#f7f7f5` | sidebar / cards / icon tile |
| `--color-text-primary` | `#f0f0f0` | `#111111` | wordmark text |
| `--color-accent` | `#e8e0d0` | `#3a3530` | **the lens dot**, icon "L" |
| `--color-border-secondary` | `#2a2a2a` | `#d4d4d0` | icon tile border |
| `--font-display` | `'Canela', Georgia, serif` | — | wordmark + icon glyph |

**Lens-dot spec (em-relative, theme-agnostic):** diameter `0.16em`, `margin-left 0.12em`, `margin-bottom 0.14em`, baseline-aligned (`align-items: flex-end`), fill `var(--color-accent)`. Verified legible from 18px (sidebar) up to 48px.

The wordmark works unchanged in light mode because it references `--color-text-primary` and `--color-accent`, which the `.light` class remaps. No light-specific code required.
